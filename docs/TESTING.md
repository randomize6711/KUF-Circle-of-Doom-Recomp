# Testing

Run everything with `ctest --test-dir build/linux-amd64-relwithdebinfo -j4` (see "The full suite within memory"): **1,917 tests** as of M7 feature 2 (the menu pointer) with
`-DKUFCOD_SMOKE_TEST=ON` (smoke, capture, menu, gameplay, savegame, campaign, settings, camera, display and timing
game runs included; they are opt-in). The campaign tests and the settings/camera runs that start from the Shadow
Depths save (and the camera fault injection, which reads their logs) are registered only where that fixture
exists (build/m6-saves/, outside Git): elsewhere they are not registered and nothing is reported as skipped.
Results per milestone are in PROGRESS.md.

## The full suite within memory

The game runs take one `game_gpu` resource lock, so one game runs at a time whatever `-j`; the other slots run
checks and unit tests. A game process uses 1.1-1.5 GB, a run with a build freeze (the alpha sweeps) up to 6.8 GB
(a copy of guest memory, test-only); the largest check 2.4 GB (`effect_check_presentation_native_4k`; all 315
non-game tests measured alone, D5 validation). With the desktop's applications using about half
of a 32 GB machine, use `-j4` (D5: `-j6` with a 14 GB check exhausted memory, KNOWN_ISSUES K50). The D5 validation
ran the suite in batches of whole fixture groups (`--tests-from-file`; a test's setups and checks in the same batch)
with a 1 s memory sampler; docs/HIGH_FPS.md 22.2. A check that reads many captures should read them as it uses them
and run under `tools/peak_rss.py --max-mb N --`.

## How the instruction suites are built
1. `tools/ppc_asm_sandboxed.sh` assembles `*.s` with the SDK's prebuilt PowerPC binutils inside
   `bwrap` (no network, read-only system, write access only to the output dir).
2. Our source-built `rexglue recompile-tests` turns the binaries plus `#_ REGISTER_IN/OUT` directives into
   Catch2 tests.

`tests/ppc_asm/*.s` and `tests/ppc_asm_divergence/*.s` are generated by `tools/gen_insn_tests.py`. Expected
values there are computed independently (numpy IEEE float32 arithmetic and exact rationals), not taken
from ReXGlue. Regenerate after editing the generator: `python3 -I tools/gen_insn_tests.py tests/ppc_asm`.

## Coverage tools
- `tools/audit_coverage.py`: every emitted instruction's address is reconstructed and its mnemonic
  checked against LLVM's disassembly of the original image. Lists every code word not emitted.
- `tools/insn_test_coverage.py`: which instructions the game uses and which have a semantic test. As of
  M1, 238 of the 314 distinct instructions (64.5 % of sites) have a dedicated semantic test. The other 75
  are plain loads/stores, branches and system instructions that every test exercises (35.5 %).
  Untested: `mffs` only (5 sites; its upper result bits are undefined, so it can't be asserted exactly).
  Run with `thirdparty/rexglue-sdk/tests/ppc/asm tests/ppc_asm` as the asm dirs; the report goes to
  `build/analysis/v1/insn_coverage.txt`.

## Smoke test (sandboxed game run)
`python3 -I tools/smoke_test.py [--seconds 300]`, or `ctest -L smoke` after configuring with
`-DKUFCOD_SMOKE_TEST=ON`. It needs the user's game files, a Vulkan GPU and a built `linux-amd64-audit`
tree. It runs the game in the sandbox with a timed clean exit and passes only on positive evidence: exit
0 via the timed path; ≥ 90 % of 30 fps in every 10 s interval after warm-up; the boot archives, shader
bundle, BGM banks and title movie opened; a 50 MHz guest timebase; no runtime errors; a bounded run
directory; every exercised partial or stubbed import reviewed. The report goes to
`build/runs/<id>/smoke-report.txt`. A negative control (`-- --allow_game_relative_writes=true`) fails, as
it should.

M2 result: **PASS**: 300 s, 8,936 frames (min 299 per 10 s), 26 files, 105 imports called, 4.5 MB.

Since M3 it also captures every 300 frames and checks them (`images`: valid, not blank, plausible
statistics, and the title/attract movies keep changing for the whole run), checks resident memory after
warm-up (`memory`, from `rss_mb` in run-summary.json) and summarises GPU warnings (`gpu`). Captures don't
count toward the run-directory limit. M3 result: **PASS**: RSS 1,082–1,083 MB from 60 s to the end (1 MB
growth), 29/29 captures valid, minimum frame-to-frame change 2.24, 1 GPU warning (one skipped
presentation at boot while an async pipeline compiled).

## Screenshot regression (M3)
- `tools/capture_check.py stats|check|baseline|compare` (see its docstring). Expectations are statistics
  only (`tests/capture/title_v1.toml`); captures and references are game content and stay in `build/`.
- `python3 -I tools/capture_test.py [--baseline]`: sandboxed 40 s run, then check (and compare when
  references exist). Create references with `--baseline` only after a visually confirmed run.
- On this machine the captures are bit-identical between runs (block difference 0.00). The comparison
  tolerances (8×8 block averages, mean ≤ 3.0, ≤ 1 % of blocks off by > 24) are for other GPUs and drivers.
- Negative control: the pre-K13 run (`build/runs/m3-cap-1`) fails stats, blank and animation checks.

## Merging a milestone (fail-closed)

`tools/safe_merge.sh <branch> [--new-branch <next>]` is the only merge path. In one `set -e` process it
checks a clean tree (SDK submodule at its pinned commit with exactly `patches/rexglue-sdk` applied), that
`main` is an ancestor (fast-forward), builds both trees, runs the full ctest suite (100 %, nothing skipped,
at least `KUF_MIN_TESTS`, default 1,615 tests), re-checks HEAD and tree, verifies the game folder against
its SHA-256 manifest (`tools/verify_game_dir.sh`, also detects added or removed files) and the tracked
paths (`tools/check_tracked.py`). Any failure prints `MERGE ABORTED` and exits before `git merge --ff-only`.
Log: `build/logs/merge-<branch>.log`.

## Diagnostics
- `tools/run_sandboxed.sh -t <s> -n <id> [--gpu] [--gdb script]`. A crash (exit 70) is symbolized
  automatically into `build/runs/<id>/crash-report.symbolized.txt`.
- gdb inside the sandbox: scripts in the M2 history (`handle SIGTRAP nostop nopass` is required, K11).
  `tools/symbolize_gdb_dump.py` turns `thread apply all bt` into guest call stacks.
