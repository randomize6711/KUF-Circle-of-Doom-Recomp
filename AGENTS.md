# AGENTS.md — rules for coding agents working on kuf-cod-recomp

Native PC port of **Kingdom Under Fire: Circle of Doom** (Xbox 360, 2007) by static recompilation on the
ReXGlue SDK. Read `docs/PROGRESS.md` first (current milestone and what is verified), then `docs/ROADMAP.md`.

## Hard rules

1. **The original game folder is read-only**:
   the game folder (`KUF_GAME_DIR`, or the path in the untracked `.game_dir`). Never write, create, rename or delete
   anything there. Tools only read it (`tools/stage_input.sh` copies `default.xex` out once).
2. **Never commit game-derived data**: no XEX/PAK/SOX/XWB/WMV, no extracted assets, no `generated/default/`
   C++, no images, disassembly, screenshots of game content or traces. `.gitignore` covers the usual paths.
   Addresses and boundary facts in `config/<ver>/*.toml` are fine.
3. **Never run the game binary bare**, not even `--help`. Use `tools/run_sandboxed.sh`. It provides a
   read-only game dir, writes only to `build/runs/<id>/`, has no network and no display or audio sockets,
   and enforces a timeout. Build successfully first. To learn options, grep `REXCVAR_DEFINE` in the SDK.
4. **Third-party prebuilt binaries run only sandboxed** (e.g. the SDK's PowerPC binutils, via
   `tools/ppc_asm_sandboxed.sh`). Do not turn on `REXGLUE_BUILD_TESTS`, which would run them unsandboxed.
5. **Git**: local repository, no remote. No force-push, no history rewrites, no deleting backups. Small
   commits after verified steps; feature branch per milestone (`m<N>/<topic>`), merged into `main` after
   approval, **only with `tools/safe_merge.sh <branch> [--new-branch <next>]`**. It is fail-closed: clean
   tree, full build, every ctest test passing, game folder unchanged (`tools/verify_game_dir.sh`) and no
   game content tracked (`tools/check_tracked.py`), then `git merge --ff-only`. Never merge by hand, and
   never put a merge in the same command line as a test run.
6. **Milestone gates**: stop at the end of each milestone and wait for approval. Do not start graphics
   modernisation, frame-rate decoupling or multiplayer work before their milestones.
7. **Clean-room**: never download, inspect or use the leaked 2006 COD source code. Use only our own
   reverse engineering, public documentation and properly licensed open source (ReXGlue/Xenia are BSD;
   do not copy GPL-3 code from UnleashedRecomp/MarathonRecomp).
8. **No system-wide changes** (packages, /etc, user config outside this repo) without approval. ReXGlue's
   install step writes `~/.cmake/packages`, which is why we use the SDK as a submodule (`REXSDK_DIR`).
9. **Report honestly**: generated code is not success. Claims need a build, a test or a sandboxed run log.

## Layout

| Path | What |
|---|---|
| `thirdparty/rexglue-sdk` | Pinned SDK submodule (do not edit in place; carry changes as patches in `patches/`) |
| `kuf_cod_manifest.toml` | Codegen manifest (v1); includes `config/v1/*.toml` |
| `config/v1/functions.toml` | Hand-verified function boundaries (tail-jump-only leaf functions) |
| `config/v1/indirect_functions.toml` | Generated by `tools/indirect_targets.py`; do not hand-edit |
| `generated/` | `rexglue.cmake` (committed); `default/` = recompiled C++ (ignored) |
| `src/` | Host application (ReXApp subclass); future runtime overrides and game patches |
| `tests/` | `image/` (recompiled game functions), `ppc_asm/` (generated instruction tests), `ppc_asm_divergence/` |
| `tools/` | Pipeline and analysis scripts (Python is run with `python3 -I`) |
| `build/` | Presets' build trees, `input/`, `analysis/`, `runs/`, `logs/` (ignored) |

Version-specific knowledge lives under `config/<ver>/`, `build/input/<ver>/` and `build/analysis/<ver>/`. A
future title-update build gets its own version key (see docs/ARCHITECTURE.md).

## Workflow

```sh
tools/stage_input.sh v1                         # stage + verify XEX, build analysis image and disassembly
cmake --preset linux-amd64-relwithdebinfo       # configure (SDK from the submodule)
ninja -C build/linux-amd64-relwithdebinfo rexglue   # codegen CLI (first time only)
tools/codegen_iterate.sh                        # codegen + coverage audit until indirect targets converge
cmake --preset linux-amd64-relwithdebinfo       # re-run once after the first codegen (adds generated sources)
ninja -C build/linux-amd64-relwithdebinfo -j8   # build (cap memory: systemd-run --user --scope -p MemoryMax=14G)
ctest --test-dir build/linux-amd64-relwithdebinfo -j8
tools/apply_sdk_patches.sh                      # once per fresh submodule checkout (configure checks it)
tools/run_sandboxed.sh -t 90 -n <run-id> --gpu -- --kuf_exit_after_seconds=60
#   saves: build/runs/<run-id>/saves (fresh); --saves-from <run or saves dir> copies saves in (source read
#   only); --save-dir <dir> keeps saves across runs (opt-in, backed up, confirmation); docs/SAVES.md
python3 -I tools/kuf_save.py build/runs/<run-id>  # read-only save inspection (packages, manifest, leftovers)
tools/update_sdk_patch.sh patches/rexglue-sdk/<n>-....patch   # regenerate an SDK patch after editing the SDK
python3 -I tools/smoke_test.py --seconds 300    # needs the linux-amd64-audit tree built
```

After any codegen change: the audit must show **0 mnemonic mismatches**, the codegen log must contain no
`Unresolved` lines, and all tests must pass. Before finishing a milestone, also run the smoke test.
Keep `docs/PROGRESS.md` and `docs/KNOWN_ISSUES.md` current.

Only start a game run after a successful build: chain the commands with `&&`, never with `;`.

## Diagnosing runtime failures

- A fault ends the run with exit 70 and `build/runs/<id>/crash-report.symbolized.txt` (the original
  instruction, guest registers, guest stack, symbolized host frames = guest call chain).
- `--gdb script.gdb` runs the game under gdb in the sandbox. Required in every script:
  `handle SIGSEGV nostop noprint pass` (the runtime uses SIGSEGV for MMIO/write watches) and
  `handle SIGTRAP nostop nopass` (K11). Pending breakpoints on runtime-library symbols do not resolve in
  the sandbox; use generated-code lines (`kuf_cod_recomp.N.cpp:LINE`) or app hooks instead.
- Thread dumps: interrupt from a Python timer, `thread apply all bt`, then
  `tools/symbolize_gdb_dump.py`.
- To observe a game function, wrap it with `REX_HOOK_RAW(sub_X)` and call `__imp__sub_X`. Mid-asm hooks
  cannot share an address.

## Investigating guest code

- Disassembly: `build/analysis/v1/flat.dis` (VA addresses). For a range:
  `llvm-objdump -d --no-show-raw-insn --start-address=A --stop-address=B build/analysis/v1/image.elf`.
- LLVM does not decode most VMX128 encodings (`<unknown>`, or bogus Power10 names like `lxvp`). Trust
  ReXGlue's comments in `generated/default/*.cpp` for those.
- Function index: `PPCFuncMappings` in `generated/default/kuf_cod_init.cpp`.
- Logs in sandbox runs can grow quickly (fault loops). Always pass a run timeout, and trim logs afterwards.
